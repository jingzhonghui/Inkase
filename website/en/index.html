#One document, one file

Inkase is a Markdown editor. It packs the text, images and attachments into a single .mdx file — copy that one file and you have the whole document, with no "missing image" ever again.

Download free View source

##What .mdx is

It is a standard ZIP archive, not a proprietary format. Inside there are only three things: some metadata, a plain-text Markdown file, and an asset folder. Open it with any tool, ten years from now.

{
  "version": "1.0",
  "created_at": "2026-03-14T09:12:04.000Z",
  "modified_at": "2026-04-02T16:38:51.000Z",
  "title": "Project plan",
  "encoding": "UTF-8",
  "content_file": "content.md",
  "assets": {
    "images": [
      {
        "id": "img_7f3a91",
        "filename": "architecture.png",
        "path": "assets/images/architecture.png",
        "mime_type": "image/png",
        "size": 184320,
        "checksum": "sha256:9c1f…",
        "width": 1280,
        "height": 720
      }
    ],
    "attachments": []
  },
  "settings": {
    "editor_theme": "default",
    "preview_style": "github"
  }
}

The document's identity card: title, created and modified times, encoding, and the size and checksum of every image.

##PDF and images

Open PDFs and images read-only, right in a tab. No format conversion, no changes to the original file. In dark mode the whole page inverts, so long documents are easy on the eyes at night.

Product handbook.pdf − 100% + 3 / 24

Chapter 3　Deployment

Drop the .mdx into your workspace folder. Inkase scans and indexes it at startup — no extra asset server needed.

Images and attachments live inside the package and are referenced relative to content.md, so you never end up with a broken image link.

PDF export runs through the same rendering pipeline as the preview, so fonts, syntax highlighting and math all carry over.

Inversion is done with invert(.9) hue-rotate(180deg) — black on white becomes light on dark grey, while the hue of embedded images barely moves. Try the button in the top right.

  • ✓

    Read-only, nothing written

    PDFs and images render in their own tab: no conversion, no temp files. Close the tab and the original file has not changed by a single byte.

  • ✓

    Batch PDF export

    Export a whole folder at once, watch the progress item by item, and cancel midway if you like. Single and batch export share the same rendering pipeline.

  • ✓

    Images and attachments together

    Drop them in and they are collected into the document's assets/, deduplicated by content checksum. Viewers read from inside the package — never over the network.

##AI assistant

Point it at any OpenAI-compatible endpoint and it can read and write your documents and search the whole workspace. Before it touches anything, it lays out exactly what it is about to do.

Tools, approvals and permission policy are all decided locally. Your key stays in your own config, and conversations live under .inkase/conversations/ in the workspace.

  • ✓

    Every tool call is approvable

    Reading a file, searching the workspace, writing content — each one raises a card first, spelling out which file it will touch and how much. Click allow to run it, deny to stop.

  • ✓

    Permissions have edges

    Paths outside the workspace need separate authorisation, and read-only is kept apart from writable. The policy engine decides locally, with no server involved.

  • ✓

    Your model, your choice

    As long as it speaks the OpenAI API, you fill in the base URL, model name and key yourself. Conversations stay on your machine and can be cleared at any time.

##Syncv0.3.5 adds WebDAV

Pick either backend: bind a Git repository, or connect a WebDAV drive. Pull, push and conflict handling all happen in the panel — no command line required.

.inkase/ is machine-local configuration and is written into .gitignore automatically. If it is already tracked, Inkase removes it from the index before committing. A legacy .markdownPlus folder is migrated automatically when you bind.

The password is encrypted with the system credential store and kept separately — it is never written into .inkase/sync.json. WebDAV has no "commit" layer, so changes are pushed directly; each file is compared by ETag, and if the remote copy has been changed by someone else you get a conflict rather than a silent overwrite. Enabling it runs no git commands at all.

  • ✓

    Two backends, one panel

    Git goes through a repository, WebDAV connects to your own drive. Switching backends only swaps the provider — pull, push and auto-sync work exactly the same way.

  • ✓

    Conflicts are visible, never silent

    With Git you see which document, which lines, and what each side changed; WebDAV compares ETags and stops to ask if the remote copy has moved.

  • ✓

    One-click pull and push

    Buttons appear as soon as you are bound, and auto-push sends changes as you make them. New remote commits are noticed, and you are told which files changed before pushing.

##What else it does

Beyond the editor, Inkase is a complete document workbench.

Writing

Custom typography
Body font, code font and line height are all adjustable; hold Ctrl and scroll in the editor to zoom the text instantly.
Three themes
Light, dark, or follow the system.
Autosave and recovery
Your edits are snapshotted as you type, and the session is restored automatically after an unexpected exit.

Managing

Folder workspace
Browse, create, rename and drag files around, much like a file manager.
Multiple tabs
Keep several documents open at once and switch freely between them.
Full-text search
Search across files with ripgrep; Ctrl+P opens any file in milliseconds.

Interop

Import
DOCX and Markdown files, plus whole folders.
Export
Markdown and PDF, with batch export.
External change watching
If a file is changed outside Inkase you are told to reload, rather than having your work silently overwritten.
